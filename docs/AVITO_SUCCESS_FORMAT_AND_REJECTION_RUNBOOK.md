## Обязательный путь при отказе Авито

1. **Стоп.** Не запускать повторную `autoload/v1/upload` вслепую и не менять успешную московскую строку. Собрать свежий `upload_id`, `current.status`, `current/items`, `section`, коды и сообщения именно целевого `Id` (не брать исторический `last_successful`).
2. **Валидатор Авито:** открыть https://autoload.avito.ru/format/xmlcheck/ и отправить адрес *актуального* XML. Программно публичный интерфейс использует `POST https://autoload.avito.ru/api/v2/public/xml_checker/from_url/` с телом `text/plain`, содержащим ссылку на XML; ответ `data.id` — номер проверки. Читать `GET /api/v2/public/xml_checker/result/{id}/`. Сообщение «Отчёт в работе» — НЕ итог. Тайм-аут/сбой сети — НЕ отказ валидации. Не утверждать «проверка пройдена», пока нет содержательного результата.
3. **Разбор ошибок:** сопоставить `Id` каждого объявления с подробным отчётом; исправить **только соответствующую** проблему, не меняя случайно город/цену/фотографии другого объявления. Типовые ошибки нашего опыта: `1013` — неправильный постоянный `Id`/привязка объявления, `1008` — неверная категория, `1316` — URL фото ведёт к HTML, редиректам или недоступен, `429` — слишком частый запрос (ожидать разрешённый интервал). Другие коды — расшифровывать по свежему тексту Авито; не предполагать смысл без отчёта.
4. **Локальная и публичная preflight-проверка:** XML корректен; оба `Id` уникальны; Москва точно совпадает с эталоном, кроме явно одобренных изменений; Петербург отличается от Москвы лишь `Id`, отсутствием `AvitoId` и значением `Address`; шесть ссылок каждой строки дают HTTP 200 с `image/*`, по возможности сверять SHA-256; `ListingFee=Package` / `AdStatus=Free`; никакой `PackageSingle`, `BBL`, `PackageBBL` или платных сервисов без прямого разрешения владельца.
5. **Повторная официальная проверка** исправленного XML. Если отчёт задерживается, помечать его как «в работе», а не как успешный. Отдельная категория модерации/тарифный отказ может не обнаруживаться валидатором; проверять отчёт реальной автозагрузки.
6. **Публикация после cooldown:** один `POST /autoload/v1/upload` только после проверки, что автозагрузка включена и профиль содержит наш правильный публичный `feed_url`; учитывать лимит не чаще 1 POST в час и возможные дополнительные ограничения. `HTTP 200` — только принятие запуска, не доказательство публикации.
7. **Приёмка по самому Авито:** свежие `/autoload/v4/uploads/current` + `/autoload/v4/uploads/current/items`, желательно section `success_published` целевого `Id`; прямой `/core/v1/items?status=active` должен показать **оба** действующих объявления (Москву №8347570435 и новый Петербург с отдельным реальным Avito ID), цену 5000 и ссылки с соответствующими городами. Если Авито отклонил новую карточку, НЕ считать выполненной, не повторять без новых исправлений. Отдельно проверить шесть фото в самой карточке, когда доступен UI или API.

## Защита от непреднамеренных платежей и повреждения действующей публикации

- `ListingFee=Package` расходует ТОЛЬКО доступный пакет/квоту; не включает разовую оплату с кошелька. При отсутствии пакета новое объявление может не выйти — это предпочтительнее неожиданного платного размещения.
- `AdStatus=Free` исключает платное продвижение.
- Нельзя заменять содержание Москвы, отключать её или удалять строку из XML ради публикации Петербурга.
- В категории «Услуги» Авито предусматривает возможность одной услуги в разных городах при реальной доступности. Используем удалённую услугу, не придумываем адрес офиса; конкретное решение об одобрении принимает Авито.
- Запись `success_published` в **исторической** последней успешной загрузке не доказывает текущую публикацию. Проверять актуальные состояния и свежую карточку.
