# Авито: доверенный серверный браузер — развёртывание без включения

Обновлено: 06.11.2026. Статус: **код подготовлен в черновике PR #31; сервер НЕ развёрнут и внешняя авторизация НЕ проверена**.

## Что действительно сделано

В `tools/avito_trusted_ui_worker.py` добавлен отдельный процесс, способный читать только строго определённые команды `AVITO_TRUSTED_UI_COMMAND_V1` из публичного GitHub Issue #32. Он принимает только `inventory` для `portfolio` и `public-profile`, проверяет ID владельца GitHub, UUIDv4, время действия и отсутствие лишних полей. Сохраняет локальный журнал обработанных команд, отфильтровывает дубликаты. Единственный сетевой запрос на запись — опубликование обезличенного `AVITO_TRUSTED_UI_RESULT_V1` в тот же Issue.

**Ни одной команды редактирования Авито**, входа по паролю, покупки, отправки сообщения, публикации, снятия объявлений, загрузки файлов или прямого вызова внутреннего API сайта нет. Публичный GitHub не хранит cookie, скриншоты, содержимое профиля, IP или пароли.

Владелец может в интерактивном Chromium подготовить локальную сессию и сохранить **только ссылку на вручную выбранный раздел** в режиме `bootstrap`. После этого отдельная `once`-команда при явном разрешении `--enable-browser-readonly` пытается открыть **только** предварительно одобренный URL и подсчитать видимые элементы интерфейса, используя `avito_browser_operator.inspect_controls`. Итог — только категории и счётчики. Даже успешная инвентаризация не доказывает, что произошла авторизация или что публичный прайс виден покупателю.

## Предварительные условия

1. Отдельный доверенный VPS/виртуальная машина, не сервер Gii. Статический внешний IPv4, который реально назначен хостеру и проверяется владельцем; Авито должно подтвердить допустимость доступа с этого IP либо разрешённый способ работы. **Не приобретать сервер и не заявлять одобрение IP без согласования расходов и подтверждения технического сценария.**
2. Linux с Python 3.10+ и Playwright/Chromium; доступ владельца к интерактивному графическому сеансу с защищённым подключением. Не публиковать VNC/RDP в открытый интернет и не передавать куки по почте/в GitHub.
3. Отдельная системная учётная запись без root-привилегий, приватный домашний каталог, исходящий HTTPS к GitHub/Авито.
4. Для ответа в Issue нужен ограниченный fine-grained GitHub token с правом Issues: Read/Write **только для `olegendorphine-star/ai-ecosystem`**. Хранить лишь в приватной конфигурации сервера (mode 0600), не в командной строке, Issue или репозитории.
5. Не запускать bridge через GitHub Actions; Actions выполняют только офлайн-тесты.

## Запуск после реального согласования и развёртывания

На доверенном сервере, в приватном рабочем каталоге с копией репозитория PR #31:

```bash
python3 -m pip install playwright
python3 -m playwright install chromium
python3 tools/avito_trusted_ui_worker.py once --dry-run
```

Последняя команда проверяет GitHub-команды и **не открывает браузер**.

В интерактивном сеансе владельца после подтверждения допустимости данного IP:

```bash
python3 tools/avito_trusted_ui_worker.py bootstrap --purpose public-profile
python3 tools/avito_trusted_ui_worker.py bootstrap --purpose portfolio
```

Владелец самостоятельно авторизуется штатными средствами, проходит 2FA/CAPTCHA и вручную открывает нужный раздел. Скрипт сверяет домен и путь, запрашивает `CONFIRM` и сохраняет URL в локальный `~/.local/share/avito-trusted-ui/targets.json` с доступом только владельцу. Каталог `owner-session` и cookies остаются только в приватной файловой системе сервера.

Для пробной **локальной** инвентаризации без публикации результата:

```bash
python3 tools/avito_trusted_ui_worker.py once --dry-run --enable-browser-readonly
```

После проверки команд и UI на данном сервере администратор может явно включить публикацию обезличенных результатов (ограниченный GitHub токен заранее помещён в переменную окружения приватной службы):

```bash
python3 tools/avito_trusted_ui_worker.py once --post-results --enable-browser-readonly
```

Для периодического выполнения можно запускать этот `once` через отдельный systemd timer, **только после живой приёмки**. Не создавать автоматически постоянный процесс до подтверждения доступности и штатного входа.

## Приёмка

- Согласован IP и нет ошибки сетевого доступа от Авито.
- Владелец вручную вошёл и открыл оба раздела в интерактивном Chromium.
- Успешная локальная инвентаризация без чтения полей, cookie и скриншотов.
- Публичный Issue #32 содержит только отчёт `observed_controls` с агрегированными счётчиками либо `blocked` с фиксированной причиной. В отчёте `public_profile_updated=false`, `price_list_visible=unverified`.
- Контроль: ложный автор, неверный UUID, истёкшая команда, URL/селектора/тексты в команде и повторный UUID отвергаются.
- **Отдельно:** приватный канал подтверждённых редактирований и проверка публичной карточки СПб; они ещё не реализованы. Этот read-only мост не равен полноценному управлению профилем из обычного чата.

## Ограничения

Облачные IP TinyFish динамические, выделенного IP провайдер не даёт; функция собственного прокси для аккаунта не включена и есть известная ошибка с сохранённым профилем. Статический IP **доверенного VPS**, если будет выбран, необходимо проверить и согласовать отдельно. Вход через рабочий VPN на планшете не доказывает работоспособность VPS.
