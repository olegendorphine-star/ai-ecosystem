# Авито: безопасная передача команд от чата к доверенному браузеру (этап протокола)

Дата: 06.11.2026. Статус: **офлайн-протокол реализован и покрывается тестами; живой мост и удалённый браузер НЕ подключены**.

## Зачем это отдельно от существующего GitHub-моста

Основной Issue #32 и GitHub Actions выполняют только `ping`, `check_public_feed`, `check_avito_public_access`, `check_live_avito_api`. Они не знают пароля, не хранят cookies и не редактируют публичный профиль. Репозиторий и Issue **публичные**.

Отдельный будущий исполнитель на доверенном сервере должен держать авторизованный профиль Chromium **локально, вне GitHub**, с доступом через штатно разрешённую сеть и с ручным прохождением владельцем CAPTCHA/2FA. Нельзя загружать каталог профиля Chromium, скриншоты, логины, IP, JSON-планы с личными данными или приватные результаты в публичный Issue.

Поддержка Авито 06.11 подтвердила возможность автоматизации собственных альбомов портфолио и публичного профиля, но не предоставила API. Пока штатная удалённая авторизация и исходящий IP браузерного агента не согласованы. Задача не зависит от того, что VPN на планшете владельца работает: его IP нельзя выдавать за IP удалённого исполнителя.

## Что добавлено сейчас

`tools/avito_trusted_ui_handoff.py` — **offline-only** модуль формата команд и обезличенных ответов. Не содержит GitHub-сетевого клиента, не запускает Playwright, не делает Avito API-запросы, не создаёт публикации и не читает личные данные.

Пример подготовки команды в локальной среде (печать, **НЕ отправка**):

```bash
python3 tools/avito_trusted_ui_handoff.py self-check
python3 tools/avito_trusted_ui_handoff.py prepare --purpose portfolio
python3 tools/avito_trusted_ui_handoff.py prepare --purpose public-profile
```

Будущий публичный формат `AVITO_TRUSTED_UI_COMMAND_V1`: только `schema`, `request_id` (UUIDv4), `action=inventory`, `purpose=portfolio|public-profile`, `issued_at`, `expires_at` (TTL не более 10 минут). **Никаких URL, селекторов, редактируемого текста, файлов или токенов в командах нет.**

Приём команд: строго из GitHub API с проверкой GitHub `user.login` и `user.id` владельца, даты, TTL, точного списка ключей и локального журнала уже обработанных UUID. Комментарии с другими командами отклоняются. Это **схема**, а не уже запущенный приёмник — новый комментарий сейчас НЕ будет обработан автоматически.

После локальной *подтверждённой* авторизации доверенный исполнитель сможет вызвать ранее созданный `avito_browser_operator.inventory_controls`, а `sanitized_inventory` оставит только целочисленные счётчики категорий и классов управления. Формат `AVITO_TRUSTED_UI_RESULT_V1` всегда включает `public_profile_updated=false` и `price_list_visible=unverified`; он не передаёт содержимое полей, адреса страниц, IP, персональные сведения или скриншоты. По умолчанию результат `blocked/no_verified_session`. Даже `observed_controls` не означает успешную публикацию.

Тесты: `tests/test_avito_trusted_ui_handoff.py`. Запуск только офлайн через `.github/workflows/avito-browser-operator-offline.yml`.

## Что ещё НЕ реализовано

1. Отдельная доверенная машина с разрешённым исходящим IP и подтверждённым входом владельца в Авито. Не использовать сервер Gii без отдельного решения.
2. Живой клиент чтения событий GitHub + защищённое хранение replay state на доверенной машине.
3. Проверка действительного URL и элементов UI для портфолио/публичного профиля и устойчивого режима повторного использования авторизованной сессии.
4. Проверка результата на покупательской витрине, включая PriceList Санкт-Петербурга.
5. Любые изменения профиля/фотографий из чата. Для них позже потребуется **не публичный Issue**, а приватный проверяемый канал команд, отдельное явное подтверждение владельца, ограничения на действие, журнал аудита и обратимый тест. До этого запрещено расширять `ALLOWED_ACTIONS` текущего моста или автоматически сливать PR №31.

## Критерии приёмки следующего этапа

Получить от TinyFish фактический IP исходящего браузерного запуска или согласовать доверенную среду с Авито; настроить штатный вход без обхода 2FA/защит; выполнить read-only inventory только локально; проверить, что публичный ответ содержит исключительно разрешённые счётчики; затем отдельно разрабатывать защищённый приёмник и живые тесты.

**Секреты и рабочие сессии никогда не публиковать в GitHub.** Этот модуль сам по себе не является полной автоматизацией профиля.
