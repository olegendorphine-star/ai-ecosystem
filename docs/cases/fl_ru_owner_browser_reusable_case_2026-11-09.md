# FL.ru: управляемый серверный браузер, сохранение сессии и подтверждаемые действия
**Инженерный кейс и материал для продуктового масштабирования · версия 1.0 · 09.11.2026**

> Статус: испытанный прототип на собственном VPS и собственном аккаунте, **не** тиражируемое готовое решение и **не** разрешение на коммерческую автоматизацию FL.ru. Сведения о цене, эффекте и доступности функций ниже отделяют доказанные результаты от предположений.

## 1. Суть проекта и исходные ограничения

Цель владельца: из обычного чата управлять своей рабочей средой FL.ru, находить заказы, вести портфолио и учёт откликов, работать без постоянно включённого ПК, повторных входов и ручных команд в Termux. Использовать **уже существующий VPS**, GitHub и Google Диск; платные действия без отдельного согласования запрещены.

Основной фрилансерский аккаунт — `olegendorphine`. Отдельный аккаунт заказчика `olegendorphine2` не задействуется. Операции на сайте могут быть разрешены владельцем, но должны отдельно соответствовать требованиям самой площадки.

**Правовое/платформенное ограничение:** 08.11.2026 поддержка FL.ru сообщила письменно: открытого API нет, коммерческая автоматизация действий на FL.ru не разрешается, отклики следует отправлять вручную. Разрешены официальный Telegram-бот уведомлений и RSS. Поэтому демонстрация технической возможности отправки не является основанием продавать или включать массовый автопостинг на FL.ru. Для тиражирования использовать официально разрешённые интеграции и ручной шаг там, где площадка его требует.

## 3. Архитектура, потоки и границы доверия

```text
Собственник / обычный чат ChatGPT
  ├── подготовка ТЗ, текстов, решений и статусов
  ├── подключённый GitHub: изменение кода / чтение CI
  └── подключённый Google Drive: каноническая память и журнал
           │
      GitHub Actions (внешний инициатор, не хранит FL cookies)
           │ SSH BatchMode, pinned known_hosts, ограниченные Secrets
           ▼
  Имеющийся VPS / не-root пользователь
     ~/.fl-agent/                    приватная среда
       ├── xvfb-runtime/             локальные Xvfb/xkbcomp/XKB/fonts
       ├── fl_rootless_owner_desktop.py
       ├── profile/storage_state.json  секрет! только VPS, chmod 0600
       ├── fl_session_watch_status.json приватный статус, chmod 0600
       └── одноразовые файлы-блокировки и маркеры попыток
           │
      Изолированный Xvfb + headed Chromium + Playwright Context
           │ HTTPS только на разрешённом домене
           ▼
                         FL.ru
```

**Ручной вход:** отдельная временная панель на `127.0.0.1:8991` (не постоянный публичный CDP) через ограниченный HTTPS Quick Tunnel. Защита: короткое время жизни, высокоэнтропийный токен в URL fragment, выдача токена владельцу в зашифрованном RSA-OAEP сообщении, HttpOnly/Secure/SameSite cookie, CSRF/Origin/Host validation, запрет анонимного доступа к снимкам, действие только на проверенном HTTPS-домене. Туннель и ссылка истекли и не являются постоянным адресом. Ключи, пароли, cookies, полные одноразовые ссылки и кадры закрытого кабинета не помещать в GitHub, Drive или коммерческий кейс.

**Сохранение сессии:** `/api/save` сохраняет Playwright storage state атомарно только если на FL.ru есть доказательства входа **именно владельца** (приватные настройки, ожидаемый идентификатор учётной записи, отсутствие формы входа); `Browser.open` восстанавливает state только при корректных owner/mode/size. Доказан рестарт браузера; это не бессрочная авторизация — FL может отозвать сессию.

**Запуск без root:** системная среда не содержала работающего `/usr/bin/xkbcomp`, из-за чего Debian Xvfb завершался. Был найден конкретный hardcoded бинарный путь в Xvfb; в **приватной временной копии** бинарника заменён строго один литерал на равноразмерный приватный путь с симлинком на пользовательский `xkbcomp`. Системные файлы не меняются. Это исследовательский workaround для данного VPS, **не** стандарт установки на клиентские серверы: перед тиражированием заменить поддерживаемой инсталляцией Xvfb/пакетов или контейнерным runtime, проверить лицензии и безопасность сборки.

## 4. История разработки и устранённых проблем

1. **08.11:** браузерный вход с VPS вызывал дополнительную SmartCaptcha; через временные облачные туннели терялась доступность. Поддержка FL.ru подтвердила активацию аккаунта и отсутствие разрешения на коммерческую автоматизацию.
2. **08–09.11:** проверены Headless Chrome, fontconfig, `xkbcomp`, XKB map, private Xvfb runtime, proot/bind. Большинство ранних сбоев относились к графической среде и тестам, а не к FL-сессии. Исправлена синтаксическая ошибка собственной синтетической XKB-карты.
3. **09.11:** найдено и протестировано решение с временной приватной копией Xvfb; headed Chromium и настоящий FL login HTML работали. Источник: `tools/fl_rootless_xvfb_relocate.py`.
4. Запущена одноразовая owner-only панель для **ручного** входа с телефона и шифрованная выдача ссылки. Туннель нестабилен как постоянный транспорт и служит только входом; после TTL истекает.
5. **Блокер сохранения:** сначала `/api/save` возвращал `login_not_verified` из-за хрупкого сравнения устаревшего URL или из-за открытия домашней страницы вместо настроек. Исправлено на проверку фактического DOM владельца, не по одному URI; затем через локальный `/api/go(settings)` и `/api/save` сессия сохранена. Исходы: [42570699654](https://github.com/olegendorphine-star/ai-ecosystem/actions/runs/42570699654), [42570872025](https://github.com/olegendorphine-star/ai-ecosystem/actions/runs/42570872025).
6. Мониторинг сначала выдавал ложную ошибку из-за отсутствия `sys.path` при импорте серверного модуля и из-за жёсткой проверки URI. После исправления [42571657209](https://github.com/olegendorphine-star/ai-ecosystem/actions/runs/42571657209) — `healthy` с первого запуска.
7. Проверена выдача списков заказов, анализ ТЗ, бюджетов, форм и признака «Для всех» с использованием только чтения. Изучены тексты заказов и исключены вакансии без права на ИИ и заявки с неподтверждённым опытом.
8. Выполнен разовый тест двух явно согласованных откликов. Ключевой сбой: после отправки первого действия браузер выбросил ошибку; второй job превысил таймаут. **Обновление интерфейса в новом браузере** подтвердило оба отправленных отклика. Нельзя при ошибке транспорта вслепую повторять отправку.
9. Пользователь самостоятельно отправил ещё два предложения, и независимая проверка показала их в «Моих откликах». Итоговый реестр синхронизирован с Google Drive.

Это подтверждённый архитектурный разрыв, который нельзя копировать при масштабировании. Все изменения аккаунта в промышленной системе должны проходить единый централизованный шлюз политик, а старые экспериментальные workflow надо архивировать/снять с триггеров после аудита.

## 7. Надёжность, безопасность и ошибки

- Только подтверждённый владелец, верификация origin/HTTPS/допустимого хоста; аккаунт заказчика и сторонние аккаунты не использовать.
- Пароли, OTP, CAPTCHA, session cookies и приватные вложения никогда не передавать в CI-логи, Drive, публичный GitHub или рекламный кейс. State локально в закрытой директории, chmod 0600; секреты SSH в GitHub Secrets; pinned host keys.
- Не обходить CAPTCHA, rate limits, API-лимиты, платные барьеры. При запросе login/CAPTCHA — `manual_attention_required`.
- Ошибки разделять: **transport error / browser error / auth expired / business action rejected / action confirmed**. Успешный CI и даже клик по кнопке не гарантируют успешной бизнес-операции.
- Внешние записи проводить по схеме `intent -> unique idempotency key -> action -> independent read-after-write -> confirmed/unknown`. При `unknown` не делать повтор без независимой проверки.
- Журнал должен содержать: job ID, дату, канал, статус, текст/версию предложения, предложенную цену и срок, подтверждение площадки, следующий шаг, ответ заказчика. Никаких секретов и персональных сведений клиентов без необходимости.
- Контрольная периодичность 6 часов — **не SLA**: GitHub Scheduled Actions могут задерживаться или пропускаться, а Cloudflare Quick Tunnel не даёт постоянного endpoint.
- Проверки работают только пока существуют GitHub, рабочий SSH, приватные файлы VPS, активная сессия FL.ru; нет отказоустойчивого multi-region or HA контура, резервный вход остаётся ручным.

## 8. Что здесь повторяемо, а что зависит от FL

**Повторяемые продуктовые модули (для площадок с разрешёнными интеграциями):**
1. Серверный браузер / разрешённые API адаптеры, запуск без постоянного ПК.
2. Безопасный one-time owner onboarding + обновление сессии вручную при необходимости.
3. Хранилище приватного state и строгая изоляция пользователей.
4. Watchdog/health/status и оповещения, восстановление технической среды.
5. Read-only discovery → квалификация заказов → формирование адресного черновика → human approval.
6. Журнал кандидатов/откликов/диалогов/договоров/оплат на внешней памяти.
7. Независимая проверка каждой операции и защита от дублей.
8. Тесты политик, технических сбоев и безопасности.

**Специфично для FL.ru:** структура DOM, видимость «Для всех», «Отправить отклик»/«Редактировать отклик», требования CAPTCHA, изменение URL настроек, отсутствие открытого API, текущий запрет коммерческой автоматизации. Нельзя обещать работоспособность на других площадках или бесконечное сохранение сессий без нового пилота.

## 9. Коммерческий потенциал и модель тиражирования

Продавать **не бота, который обходит ограничения FL**, а легальную систему управления поиском заказов, информацией и деловой коммуникацией там, где доступ разрешён: выявление подходящих заказов, подготовка персонализированных предложений, единый журнал, напоминания, анализ конверсии, контроль входящих, Human-in-the-loop. Это самостоятельный продукт для фрилансеров/небольших агентств и **отдельное** направление от персонального «Штаба» и бизнес-интеграций.

Гипотезы (не доказанная экономика): месячная подписка за мониторинг/учёт; платное внедрение/миграция данных; отдельная настройка интеграций с CRM/почтой/Telegram. Предварительный ROI измерять по времени ручного поиска, доле релевантных заявок, ответам, заключённым договорам и чистой прибыли после затрат. **Пока 0 подтверждённых оплаченных заказов**: заявлять доказанную конверсию или окупаемость нельзя. Число «9 откликов» — показатель активности и способности зафиксировать операцию, а не PMF.

В оценку экономики обязательно включить: VPS, лимиты AI/токены, время ручной авторизации, поддержку, сбои и риск блокировки, CI минуты, хранение, персональные данные и обновления DOM. Не устанавливать ценник на основании одного успешного технического теста.

## 10. План следующей итерации (до первых внешних клиентов)

**P0 — аудит и заморозка рисков:** убрать случайные повторные триггеры одноразовых submit-workflow; обеспечить один policy gate **для всех** модулей изменения аккаунта, запрет оплат без отдельного подтверждения, журнал подтверждений; не предпринимать коммерческие действия на FL без разрешённого способа.

**P1 — стабильность:** контроль 7–14 дней без пропуска мониторинга, измерение доли `healthy`, среднее время обнаружения сбоя, частота ручных входов; независимый сценарий восстановления после выключения Chrome/VPS; регулярная проверка GitHub секретов и прав, резервная копия **не секретного** кода/журнала. Авторизационные state-файлы не архивировать на общий Диск.

**P2 — продуктовый слой:** один обезличенный пилот на разрешённом канале: структурированный поиск 10–20 карточек, ≥90% проверяемых ссылок и корректных дат, персонализированные черновики, одобрение оператором, подтверждённый журнал без дублей, отслеживание ответов. ### 12.5. Риски и меры, обязательные перед коммерческим повторением

1. **Платформенное разрешение**: письмо FL.ru от 08.11 действует как основание не обещать и не включать коммерческую автоматическую отправку/изменение. Факт владельческого разрешения сам по себе не заменяет разрешение сервиса. Официальный API отсутствует; использовать ручное подтверждение, RSS/бот и разрешённые каналы.
2. **Единый policy enforcement**: исторические одноразовые сценарии обходили \`fl_operator_policy.py\`, несмотря на fail-closed логику в самой функции. Не выпускать продукт с параллельным обходным контуром; инструментировать все write paths, ограничить права CI, добавить тесты отказа/отзыва approval.
3. **Бизнес-идемпотентность**: \`intent\` до действия, уникальный ID, проверка владельца, independent readback; \`unknown\` блокирует повтор. CI \`success\` ≠ действие принято, CI \`failure\` ≠ действие не принято.
4. **Приватность**: secret/cookies, API-токены, телефоны, OTP, CAPTCHA, приватные сообщения, изображения кабинета и временные ссылки никогда не отправлять в открытый GitHub, Drive или публичный кейс. Для передачи материалов — приватный доступ и конечный TTL; журналы — обезличенные.
5. **Экономика**: реальных договоров и оплат пока нет, ROI и конверсия не доказаны. Измерять трудоёмкость/время ручного поиска, число релевантных карточек, переходы к ответам/договорам, стоимость поддержки и отказов.
6. **Надёжность**: \`xkbcomp\` binary workaround и Quick Tunnel — технический пилот, не тиражируемая архитектура. Тест 7–14 дней, мониторинг частоты ручного логина, резервный план штатного доступа, поддерживаемый Xvfb/browser runtime и ручная деградация.
