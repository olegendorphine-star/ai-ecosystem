# Авито: управление всем профилем без переписки — контрольный план

Дата: 05.11.2026. Поручение владельца: **сосредоточиться на полном управлении аккаунтом, объявлениями, настройками, прайс-листом и платными инструментами; переписка пока не нужна**.

## Основное различие

«Есть API-токен» != «есть полное управление кабинетом». Официальный API покрывает только опубликованные методы, а часть личных настроек может требовать авторизованной работы в веб-интерфейсе. Не обещать «всё» до подтверждения на конкретном аккаунте.

## Новый шаг: безопасный реестр API-полей

PR к этому документу добавляет tools/avito_profile_inventory.py и тесты. Скрипт **в ручном режиме и только после отдельного согласия** выполняет 1 запрос OAuth, несколько GET к собственным данным, GET дерево категорий и (если найдена подходящая категория) GET её допустимых полей. В публичный лог выводятся только HTTP-коды, булевы признаки активного состояния и имена из строгого белого списка XML-полей, никакие секреты, клиентские данные и URL фида.

Ветка Pull Request запускает только offline тесты. Реальный GET можно запустить лишь после ревью/слияния в main при workflow_dispatch с approve_readonly=true. Это не автоматическая публикация и не полное право записи.

Официальные API-операции: https://developers.avito.ru/api-catalog/autoload/documentation (userDocsTree / userDocsNodeFields), https://developers.avito.ru/api-catalog/item/documentation, https://developers.avito.ru/api-catalog/auth/documentation .

## Дальнейшая архитектура управляющего контура

1. **Inspect**: права, профиль, реестр объявлений и их статусов, тариф, доступные операции; задержки и ошибки.
2. **Prepare**: проект изменения и diff, список объектов/ID, прогноз стоимости, список полей и подтверждение того, что они допустимы в категории.
3. **Validate**: локальные тесты, официальный валидатор XML и safeguards для всех объявлений.
4. **Execute**: отдельная разрешённая операция с проверкой разрешений. Не вызывать write на обычном push и не объединять разработку с действующим фидом.
5. **Verify**: свежий GET, результат модерации/прайс на витрине, финансовый статус, audit-log.
6. **Synchronize**: Google Drive как операционная память, GitHub как код и проверяемые артефакты.

### Критерий «полный доступ»

Составить полный реестр функций кабинета и для каждой отметить один из статусов: работает API; работает в браузере; требуется действие владельца; не поддерживается/не доказано. **Только после этого** обещать соответствующий объём автономности. GitHub Actions — исполнение по событиям/расписанию, а не постоянный интерактивный доступ в браузер.

Запрещено включать автосписания, повышать бюджеты, менять безопасность/платёжные данные, публиковать/снимать объявления или редактировать профиль без проверенного плана и нужного разрешения. 


## Решение по основному препятствию — 05.11.2026

Прямой приоритет владельца: **«Вначале нужно решить вопрос полной автоматизации Авито, портфолио, профиль необходимо чтобы ты могла всё»**. Поэтому производство графики и контента портфолио отложено ДО подтверждения механизма внесения изменений. Не строить дополнительные фиды и новые объявления в качестве замены требуемому контролю над публичным профилем.

### Реальная матрица доступа на 05.11.2026

| Действие | Подтверждено | Уровень уверенности | Что нужно |
|---|---|---|---|
| Список и статусы объявлений | Прямой Avito API HTTP 200 | Подтверждено | Поддерживать мониторинг |
| Редактирование полей объявлений | XML, публичный валидатор и работающий фид | Подтвержден механизм | Проверять результат модерации |
| Прайс-лист | Подтверждён как поле категории, включён в рабочий XML СПб, публичный валидатор прошёл | Применение на витрине ещё НЕ подтверждено | Приёмка СПб, потом Москва |
| Публичный профиль: имя, логотип/аватар, описание, специализация | GET /core/v1/accounts/self читает часть сведений, прав на запись НЕ доказано | Не реализовано | Официальная схема записи или разрешённый интерфейс |
| Портфолио: альбомы, названия, описание, фото | В интерфейсе Авито есть кнопка «Добавьте портфолио», программных методов не найдено | Не реализовано | Подтверждение официального API/доступа к кабинету |
| Чувствительные данные, платежи, доступы, 2FA | Только сам владелец | Не делегировано | Не пытаться автоматизировать обход подтверждений |
| Переписка | По решению владельца исключена | Вне объёма | Не обращаться к messenger API |

Не путать API **технического профиля автозагрузки** /autoload/v2/profile с публичным профилем исполнителя. Обход обычного порядка использования сайта автоматизированными скриптами может нарушать условия Авито. Никаких stealth-драйверов, обхода CAPTCHA, подделки браузерного отпечатка или передачи паролей/куки через публичный GitHub.

### Допустимые варианты архитектуры

**A. Официальный API** — предпочтительный для всех документированных операций; сохранённые GitHub Secrets, логирование, whitelist действий, ограничение частоты и проверка результатов.

**B. Отдельный авторизованный браузерный контур** — только если Авито подтверждает допустимость соответствующих действий, либо они явно выполняются как обычные действия владельца в разрешённом режиме. Однократный вход владельцем без раскрытия пароля в чат; приватное хранение сессии, не в публичном GitHub и не в GitHub Actions artifacts. Нужно тестировать реальную поддержку Авито, возможность сохранить авторизацию, обработку 2FA, прекращение при ограничении доступа; не обещать автономный режим до испытания.

**C. Если автоматическое UI-редактирование не разрешено или технически ненадёжно** — агент готовит изменения и их проверяет; отдельное фактическое применение остаётся владельцу в штатном интерфейсе. Нельзя обещать «100%» вопреки условиям платформы.
