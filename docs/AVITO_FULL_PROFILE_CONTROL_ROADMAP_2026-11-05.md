# Авито: управление всем профилем без переписки — контрольный план

Дата: 05.11.2026. Поручение владельца: **сосредоточиться на полном управлении аккаунтом, объявлениями, настройками, прайс-листом и платными инструментами; переписка пока не нужна**.

## Основное различие

«Есть API-токен» != «есть полное управление кабинетом». Официальный API покрывает только опубликованные методы, а часть личных настроек может требовать авторизованной работы в веб-интерфейсе. Не обещать «всё» до подтверждения на конкретном аккаунте.

| Объявления: редактирование, загрузка фото, публикация | Автозагрузка доказана | Проверить каждую категорию по официальному шаблону, предварительную валидацию и подтверждение live после записи |
| Прайс-лист услуг | XML-кандидат PR #16 | Читать GET /autoload/v1/user-docs/tree и /autoload/v1/user-docs/node/{slug}/fields; проверить PriceList и допустимые элементы для конкретного slug |
| Снятие с публикации / восстановление | Изучен механизм | Проверить безопасный, идемпотентный способ на тестовом объекте с согласованием |
| Платные услуги / продвижение | Прайс и баланс прочитаны | Отдельный approval gate с суммой, объектом, сроком, лимитом; readback после каждой операции |
| Статистика / отчёты / ошибки | Частично | Read-only мониторинг и корректная обработка 429 по Retry-After |

| Вход, подтверждение личности, безопасность, платёжные реквизиты | Не подтверждено | Не обходить капчи/2FA; пользователь подтверждает чувствительные действия |

## Новый шаг: безопасный реестр API-полей

PR к этому документу добавляет tools/avito_profile_inventory.py и тесты. Скрипт **в ручном режиме и только после отдельного согласия** выполняет 1 запрос OAuth, несколько GET к собственным данным, GET дерево категорий и (если найдена подходящая категория) GET её допустимых полей. В публичный лог выводятся только HTTP-коды, булевы признаки активного состояния и имена из строгого белого списка XML-полей, никакие секреты, клиентские данные и URL фида.

Ветка Pull Request запускает только offline тесты. Реальный GET можно запустить лишь после ревью/слияния в main при workflow_dispatch с approve_readonly=true. Это не автоматическая публикация и не полное право записи.

Официальные API-операции: https://developers.avito.ru/api-catalog/autoload/documentation (userDocsTree / userDocsNodeFields), https://developers.avito.ru/api-catalog/item/documentation, https://developers.avito.ru/api-catalog/auth/documentation .

## Дальнейшая архитектура управляющего контура

1. **Inspect**: права, профиль, реестр объявлений и их статусов, тариф, доступные операции; задержки и ошибки.
2. **Prepare**: проект изменения и diff, список объектов/ID, прогноз стоимости, список полей и подтверждение того, что они допустимы в категории.
3. **Validate**: локальные тесты, официальный валидатор XML и safeguards для всех объявлений.
4. **Execute**: отдельная разрешённая операция с проверкой разрешений. Не вызывать write на обычном push и не объединять разработку с действующим фидом.
5. **Verify**: свежий GET, результат модерации/прайс на витрине, финансовый статус, audit-log.
6. **Synchronize**: Google Drive как операционная память, GitHub как код и проверяемые артефакты.

### Критерий «полный доступ»

Составить полный реестр функций кабинета и для каждой отметить один из статусов: работает API; работает в браузере; требуется действие владельца; не поддерживается/не доказано. **Только после этого** обещать соответствующий объём автономности. GitHub Actions — исполнение по событиям/расписанию, а не постоянный интерактивный доступ в браузер.

Запрещено включать автосписания, повышать бюджеты, менять безопасность/платёжные данные, публиковать/снимать объявления или редактировать профиль без проверенного плана и нужного разрешения.
