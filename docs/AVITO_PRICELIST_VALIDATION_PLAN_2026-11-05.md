# Проверка прайс-листа Авито до изменения действующих объявлений

Дата 05.11.2026. Пользователь дал поручение продолжить доведение прайс-листа до рабочего состояния. Два объявления активны, цена каждой 5000 ₽, в категории по официальному read-only user-docs API подтверждено поле PriceList: https://github.com/olegendorphine-star/ai-ecosystem/blob/main/docs/reports/avito-profile-inventory-2026-11-05.json .

## Предварительная версия

Источник: draft PR #16 `feature/avito-pricelist-staging-2026-11-05/staging/avito-pricelist-candidate-2026-11-05.xml`. Дословная копия кандидата размещена ТОЛЬКО как `docs/avito-pricelist-validation-preview-2026-11-05.xml`, чтобы публичный валидатор мог загрузить её с GitHub Pages.

Содержит обе карточки, 6 исходных URL фотографий на каждую, базовую стоимость 5000 ₽, прежние Id и описание. У каждой добавлен кандидатный PriceList: 5000 / 30000 / 150000 ₽; **ServiceName, ServicePriceType, ServiceStartingPrice и вложенность Service НЕ подтверждены официальным шаблоном**. Вся разница между кандидатом и активным `docs/avito-feed.xml` — два отдельных блока PriceList.

## Проверка

Только однократный вызов ПУБЛИЧНОГО (не аккаунтного) валидатора Авито:
- POST `https://autoload.avito.ru/api/v2/public/xml_checker/from_url/` с единственным публичным URL файла (text/plain);
- GET `/api/v2/public/xml_checker/result/{id}/` с интервалом 15 секунд, пока не получен признак конечного отчёта либо не исчерпаны попытки;
- сохранить безопасный результат и HTTP-коды в `docs/reports/avito-pricelist-validator-2026-11-05.json`.

Сценарий `tools/avito_pricelist_public_validator.py` не получает и не использует секреты Avito OAuth. Прямые вызовы `api.avito.ru/autoload/v1/upload`, `api.avito.ru/token/`, `PUT`, изменение профиля, сообщения и покупки отсутствуют. PR запускает исключительно offline тесты; после приёмки однократный push в main с точным заголовком запускает проверку, ограниченную 05.11.2026.

ВАЖНО: даже «HTTP 200», `final_report_returned` или `success` GitHub Actions НЕ доказывают прохождения содержания XML. Поле `validation_passed` намеренно остаётся false, пока точная модель результата Авито не расшифрована. Проверить содержательные коды/ошибки в отчёте, исправить кандидат и только затем рассмотреть перенос двух PriceList в рабочий фид.

## Безопасность

- Рабочий `docs/avito-feed.xml` нельзя изменять и нельзя перезапускать автозагрузку до проверки и приёмки.
- Дополнительный preview.xml не является URL автозагрузки в профиле. Его публикация на GitHub Pages сама по себе НЕ обновляет объявления.
- Никаких новых объявлений или изменения цены, адреса, фото, AdStatus/ListingFee.
- Если официальный валидатор недоступен, сохранить код отказа; не подменять тест живой публикацией.
- После получения содержательного результата обновить Google Диск и предложить конкретное исправление.
