# Мост «обычный чат → GitHub → исполнитель → отчёт» — 06.11.2026

## Результат первого этапа

**Не нужен ChatGPT Work.** Команды из обычного чата можно размещать через подключённый GitHub в issue №32. После утверждения PR отдельный GitHub Actions workflow на доверенной основной ветке сам выполняет три **публичные операции только чтения** и пишет обезличенный результат комментарием в этот же issue. Чат может прочитать комментарий через GitHub. Это техническая проверка канала **без постоянно включённого личного компьютера и без собственного VPS**.

GitHub Actions предоставляет временный сервер-исполнитель. Это **не браузер с постоянной авторизацией**. Для реального изменения портфолио и публичного профиля потребуется отдельный безопасный браузерный исполнитель на выделенном сервере/доверенном ПК с разрешённым доступом к Авито; его подключение остаётся отдельной задачей.

## Почему используется публичный issue №32

Репозиторий ai-ecosystem сейчас **публичный**. В нём нельзя хранить пароли, API-токены, cookie, личные сведения и покупательские переписки. В issue №32 разрешаются только обезличенные команды и технические статусы.

- Issue: https://github.com/olegendorphine-star/ai-ecosystem/issues/32
- Worker: tools/avito_github_bridge_worker.py
- GH Actions: .github/workflows/avito-github-issue-bridge-readonly.yml
- Offline tests: tests/test_avito_github_bridge_worker.py

## Команды

Поддержаны только:

- ping — подтверждение, что GitHub Actions worker стартует и отвечает;
- check_public_feed — свежий GET публичного XML и сверка двух объявлений, шести изображений и PriceList СПб 5000, 30000, 150000;
- check_avito_public_access — открывается ли публичная главная Авито; не доказывает авторизации/прайс-листа.

Формат Issue-комментария: однострочный префикс AVITO_BRIDGE_COMMAND_V1, пробел, затем JSON с полями schema, command_id, action, issued_at, expires_at. UUID должен быть уникальным, UTC-время должно быть действительным, TTL не больше 15 минут. Пример ниже лишь схема: ПОДСТАВИТЬ ТЕКУЩЕЕ ВРЕМЯ, УНИКАЛЬНЫЙ UUID И ПОЛУЧЕННОЕ ВРЕМЯ ИСТЕЧЕНИЯ.

    AVITO_BRIDGE_COMMAND_V1 {"schema":"avito.bridge.command.v1","command_id":"<NEW-UUID>","action":"ping","issued_at":"<UTC-ISO8601>","expires_at":"<UTC-ISO8601-PLUS-5-MIN>"}

Команды принимаются только из комментариев GitHub-владельца olegendorphine-star, кроме всех остальных авторов. Подозрительные и просроченные команды отбрасываются. Программа не выполняет произвольные shell-команды, не принимает URL или код, не выполняет POST к Авито, не открывает чаты и не изменяет объявления. Результаты публикуются в Issue как AVITO_BRIDGE_RESULT_V1 {JSON}; копии результатов блокируют повторное исполнение. В рабочем варианте перепроверка перед новыми командами обязательна.

## Как включить Github Actions (после ревью PR)

1. Просмотреть и объединить PR в main по решению владельца. Пока PR не объединён, issue_comment workflow с новой логикой **не активен**. Не сливать автоматически без приёмки.
2. В этом обычном чате владелец просит «тест моста». Я создаю одноразовый комментарий в issue №32, например action=ping с TTL до 15 минут.
3. Workflow для issue_comment выполняет worker на GitHub-hosted Ubuntu. Его GITHUB_TOKEN с ограничением issues:write позволяет ответить комментарием. Отдельного PAT или SSH для этого этапа НЕ нужно.
4. Я читаю ответ из issue и сверяю command_id; только после фактического отчёта заявляю, что связь туда/обратно работает.

## Вариант с отдельным постоянно работающим сервером

Если позднее потребуется собственный браузер (Playwright), можно поставить этот же worker на выделенный сервер, запуская его read-only каждые 120 секунд. Потребуется отдельный fine-grained GitHub token только с разрешением Issues:write на наш репозиторий, переменная окружения AVITO_BRIDGE_GITHUB_TOKEN, доступ к GitHub HTTPS и приватное хранилище replay state. Пример безопасного ручного просмотра после получения кода:

    python3 tools/avito_github_bridge_worker.py --once --dry-run

После настройки переменной с ограниченным токеном и отдельной учётной записи сервиса:

    python3 tools/avito_github_bridge_worker.py --watch --interval 120

Токен не передавать в чат и не коммитить; не запускать на общем или чужом сервере. Не размещать рабочую сессию Авито и пользовательские изображения в публичном issue. Текущий worker умеет только 3 публичные read-only команды, поэтому для браузера потребуются дополнительная авторизация владельца, локальные права, отдельные команды и тесты.

## Что не сделано

- Скрипт не развернут на физическом сервере пользователя; сервер Gii не тронут и не будет использоваться для коммерческого проекта без отдельного разрешения.
- Нет рабочих разрешений на редактирование портфолио; это не полный оператор Авито.
- Прайс-лист СПб подтверждён только в публичном XML, не на пользовательской витрине; ограничения IP TinyFish сохраняются.
- Платежи, сообщения, платное продвижение, публикация и снятие объявлений заблокированы этим прототипом.


## Этап 2 — авторизованная проверка Avito API из обычного чата (06.11.2026)

Добавлена четвёртая команда check_live_avito_api (после ревью и слияния PR). Она вызывает ранее протестированный tools/avito_spb_pricelist_live_status.py: один OAuth POST за временным токеном и только разрешённые GET к XML-фиду, списку активных объявлений и текущему отчёту автозагрузки. Публикации, редактирование, платное продвижение, переписка и управление кабинетом недоступны. Секреты AVITO_CLIENT_ID и AVITO_CLIENT_SECRET хранятся только в GitHub Actions Secrets, не попадают в публичные комментарии или код.

Перед публикацией результата в публичном Issue №32 ответ строго сокращается до технических флагов: OAuth OK/не OK, HTTP-коды, активность Москвы и СПб, статус выгрузки, подробный результат current/items (если доступен). Имена владельца, телефон, тексты необработанных API-ответов, аккаунтные идентификаторы, токены и приватные ссылки не публикуются. Любое необработанное исключение сводится к «unavailable» без текста ошибки.

Лимит: повторное check_live_avito_api в пределах 60 минут возвращает result=cooldown без обращения к Avito API. Этим ограничиваем HTTP 429. Даже section=success_published не доказывает, что PriceList виден покупателю: поле price_list_visible_on_public_ad всегда unverified до проверки публичной страницы.

Критерий приёмки: offline unit tests и ревью PR, merge main, одна команда через Issue №32, чтение обезличенного ответа. При 429 не спамить запросами, при 403 не обходить ограничения сайта.
