# Авито API — план подключения (НЕ готовый клиент)

## Шаг 1 — право доступа

Получить подтверждение доступа и перечня API-методов для конкретного аккаунта Авито. Сохранить ссылку на актуальную официальную документацию и ответ поддержки в отдельной защищённой памяти проекта.

## Шаг 2 — согласовать минимальные операции

До написания рабочего клиента определить необходимые разрешённые методы: чтение собственных данных, подготовка объявлений, публикация, получение сообщений и/или аналитика — **только те действия, которые подтвердит провайдер и явно утвердит владелец**.

## Шаг 3 — безопасный клиент

Подготовить код с явными тайм-аутами, безопасным обновлением авторизации, разграничением прав чтения/записи, лимитированием повторов, маскировкой секретов и идемпотентностью операций публикации.

## Шаг 4 — офлайн-проверка

Mock-ответы: успешный вызов, отсутствие права, истёкший токен, HTTP 429, сбой сети, частичный сбой, повторная попытка, повторное создание записи. Ни один тест не должен обращаться к реальному API.

## Шаг 5 — допуск к реальной среде

Только после проверки доступов, разрешений, ограничений, бюджета, безопасности и отдельного явного согласия владельца на каждую новую категорию внешних действий.

**Не подменять реальный ответ Авито предположением, что любой метод API доступен.**
