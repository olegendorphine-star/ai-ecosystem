# Авито без Work: расширение диагностического контура

Статус: код подготовлен для ревью, **не проверен на живом Авито**. Никаких изменений действующих объявлений.

## Что добавлено

- `tools/avito_capability_audit.py`: ручной read-only аудит OAuth, профиля, активных карточек, профиля автозагрузки, последнего задания и элементов его отчёта. Отчёт только с кодами HTTP, булевыми статусами двух городов и безопасными итогами без приватных данных.
- Дополнительный **необязательный** тест доступности мессенджера: только GET метаданных первого чата; ответа и текста переписки в логах нет. Не вызывает отправку, маркировку прочитанным, webhook, отключение или блокировку.
- `tests/test_avito_capability_audit.py`: тесты без интернета/на фиктивных ключах, проверка запрета неразрешённых POST и отсутствия приватного текста в результатах.
- `.github/workflows/avito-capability-audit.yml`: сначала offline тесты, затем ручной запуск с явным флагом согласия и только из `main` после отдельного ревью/merge. В исходной ветке живой доступ заблокирован.

## Ограничения

1. Этот инструмент **не даёт новые API-права**. Он определяет, какие конкретные чтения уже доступны, и отделяет отказ от отсутствия записи.
2. GitHub Actions не становится постоянно работающим сервером. Данный workflow запускается только вручную.
3. Никаких платных POST/PUT или мутирующих методов. Деньги не списываются.
4. Публичный репозиторий: не писать токены, профиль, остатки денег, тексты/ID переписок и полные тела API в лог.
5. Даже HTTP 200 от `/messenger/v2/accounts/{id}/chats` не доказывает право отправки сообщений. Отправка требует отдельной технической и правовой проверки, согласия владельца и правил для ответов.
6. `PriceList` в XML **не проверен по официальному шаблону текущей подкатегории**. Черновик PR #16 сохраняется отдельно; никаких изменений `docs/avito-feed.xml` этим PR нет.
7. Московский AvitoId 8347570435 — ранее подтверждён `active`. Петербург пользователем сообщён опубликованным, но текущий оператор до отдельного live GET не утверждает собственную проверку.
8. Если список активных карточек больше 99, `spb_active_in_first_page=false` означает только «не найден в прочитанной странице».

## Порядок приёмки

1. Проверить PR, код и offline-тесты. Ничего не сливать автоматически.
2. После приёмки merge в `main` — вручную запустить `Avito capabilities — manual SAFE read-only audit` с `approve_readonly=true`. Поле messenger оставить выключенным, если отдельно не проверяем доступность этой части.
3. Убедиться, что в логах только HTTP-коды, безопасные статусы, `mutations=0`, `messages_sent=0`, `charges_rub=0`. Отчёт содержит факт доступности, а не подтверждение полноты авторизации.
4. Зафиксировать запуск/результат на Google Диске. Если потребуется полный оператор, следующий этап — отдельные методы с ролевыми ограничениями и журналом одобрения, а не бесконтрольное включение прав.
