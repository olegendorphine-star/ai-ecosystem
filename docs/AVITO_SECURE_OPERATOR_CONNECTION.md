# Avito — защищённый первый read-only тест (операторский режим)

**Статус:** подготовлено и тестируется только офлайн. Реальное подключение и права Avito пока не подтверждены.

## Что нужно

- Собственный профессиональный аккаунт Авито и разрешение на API.
- **Два значения** для персональной авторизации: `Client ID` и `Client Secret` (это не готовый `access_token`). Вводить их только в собственном доверенном терминале, не в чат AI, Issue/PR, CLI-командной строке, .env, скриншоте или логах.
- Подтверждение Авито о допустимости `client_credentials` для текущего приложения. Исторически 30.10.2026 получали `unauthorized_client`; наличие ключей само по себе ошибку не устраняет.
- Python 3.10+; доступ к https://api.avito.ru:443 непосредственно из доверенной операторской среды.

## Как проверить программу без сети

```bash
python3 -m unittest discover -s tests -p 'test_*.py' -v
python3 tools/avito_terminal_connect.py
```

## Первый реальный тест (только по отдельному решению пользователя)

Запускать **лично в своём защищённом интерактивном терминале** — НЕ внутри AI-агентского чата, автоматического workflow, расшариваемого терминала или сеанса с записью ввода. Не делегировать передачу значений модели.

```bash
python3 tools/avito_terminal_connect.py --live
```

Скрипт покажет предупреждение и попросит набрать слово `YES`. Затем спросит Client ID и Client Secret через скрытый ввод. Если терминал не поддерживает скрытый ввод — запуск прервётся. Обязателен HTTPS. Командная строка и история не содержат значения секретов. Скрипт не сохраняет их на диск.

Ограничение: **максимум один** `POST /token/` и **один** `GET /core/v1/accounts/self` только после успешного получения токена. Никаких повторов, публикаций, изменений объявлений, сообщений, баланса, загрузок или автозагрузки.

Только допустимые результаты: JSON со статусами `token` и `profile`, кодами вроде `authorized`, `read_only_ok`, `unauthorized_client`, `invalid_client`, `http_403_access_denied`. Не пересылать полный HTTP-ответ, заголовки `Authorization`, настройки Avito или ключи.

Если `unauthorized_client` повторится, **остановиться** и запросить у поддержки подтверждение типа приложения, статуса разрешений и grant type. Не перебором вариантов, не отключением проверок.

Если вам выдан только **один access token** вместо пары Client ID/Secret, эта утилита неприменима: не подставлять токен вместо secret. Требуется отдельный подтверждённый сценарий, без перехода в живой режим.

## Не путать три среды

- GitHub: хранит код и тесты, **но не секреты**.
- Google Drive: хранит паспорт и проверенные отчёты, **но не секреты**.
- Доверенный терминал владельца: вводит Client ID/Secret для одного согласованного read-only подключения. Ни у GPT-6, ни у Codex/Kimi не должно быть необходимости видеть значения секретов.
