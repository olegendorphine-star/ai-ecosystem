# Wordstat API → ChatGPT (через GitHub Actions)

Статус на 10.11.2026: **API подключён и GetTop подтверждён реальными ответами** через GitHub Actions. Следующие разделы содержат хронологию первоначального развёртывания, в том числе исторические ограничения 10 запросов/день. Актуальные правила указаны ниже.

## Текущий режим после оптимизации (ветка fix/wordstat-throughput-cache-20261110)

- Получены подтверждённые успешные вызовы GetTop по нескольким фразам в issue #162. Первый HTTP 403 исправлялся в PR #165; причина того отказа не доказана.
- **300 платных попыток GetTop в сутки UTC** (расчётный максимум **6 ₽/сутки** по тарифу 20 ₽ за 1000 вызовов), вместо временного потолка 10.
- **90 попыток за скользящий час** — ниже исходной квоты Yandex Wordstat 100 запросов/час. Совместно используемая квота может быть исчерпана другими клиентами — код не обходит лимиты Яндекса.
- **Кэш 24 часа** по нормализованной фразе, региону, устройству и объёму выдачи; попадание в кэш не вызывает Wordstat и не тарифицируется. `fresh=true` принудительно обновляет результат в рамках бюджетного лимита.
- **До 100 поисковых фраз + 20 ассоциаций в одном ответе** вместо десяти и пяти. Входное `num_phrases` от 10 до 100 (по умолчанию 100), ограничено из-за публичных комментариев GitHub.
- Для idempotency и квот просматриваются комментарии последних 24 часов 10 минут, а не вся история issue. Перед платным вызовом обязателен `started` от GitHub Actions; неоднозначные ошибки **не** повторяются автоматически.
- Ошибки API `429` помечаются как `provider_rate_limit`; ошибочный ответ без массива results диагностируется, но содержимое ошибки не публикуется.
- **Важное ограничение:** запросы и ответы находятся в публичном GitHub issue #162. Допустимы только открытые маркетинговые ключевые слова. Для закрытых клиентских материалов нужен отдельный приватный канал.

Реальный вызов после вливания изменений проверяется отдельно; офлайн тесты не подтверждают доступность API в данный момент.



## Назначение

Модуль даёт ChatGPT ограниченное управление запросами к официальному Yandex Wordstat REST API через подключённый GitHub. Локальный ПК не требуется. Отдельный инструмент Kimi, работающий Yandex Search API и другие сервисы не изменяются.

- Выполнение только для комментариев владельца в специально созданном публичном issue [#162](https://github.com/olegendorphine-star/ai-ecosystem/issues/162).
- Результаты появляются ответным issue-комментарием в формате `WORDSTAT_BRIDGE_RESULT_V1`.
- `regions` → бесплатный `POST /v2/wordstat/getRegionsTree`.
- `top` → `POST /v2/wordstat/topRequests`, в исходном workflow **ЗАПРЕЩЁН**, пока `WORDSTAT_ALLOW_BILLABLE` не станет `true` после отдельного решения владельца.
- Все исходящие URL зафиксированы в коде. Браузер, шифрование пользовательских сессий, редактирование FL.ru, Яндекс или других аккаунтов отсутствуют.

## Как активировать безопасно

1. Проверить и принять PR вручную (не сливать автоматически).
2. Ранее опубликованный в чате ключ **отозвать** и создать новый ограниченный API-ключ в AI Studio с областью `yc.search-api.execute`. У сервисного аккаунта в каталоге нужна роль `search-api.webSearch.user`.
3. Добавить новый ключ в репозиторий через **Settings → Secrets and variables → Actions → New repository secret**, имя `YANDEX_WORDSTAT_API_KEY`; добавить отдельный `YANDEX_WORDSTAT_FOLDER_ID`. **Не публиковать их в чат, код, issue, скриншоты и логи.**
4. Отправить из ChatGPT через подключённый GitHub одноразовую команду на бесплатный `regions` и проверить результат `GetRegionsTree`. Для этой проверки ID каталога не обязателен.
5. Для коммерческих данных: согласовать число тарифицируемых запросов и формат вывода. Публичные issue пригодны **только для неконфиденциальных слов**; для закрытых проектов нужен отдельный зашифрованный ответ вместо публичной записи.

## Контракт команды

Комментарий владельца на issue #162: префикс `WORDSTAT_BRIDGE_COMMAND_V1 `, затем JSON c:

- `schema`: `wordstat.bridge.command.v1`
- `command_id`: новый UUID
- `action`: `regions` или `top`
- `issued_at`, `expires_at`: ISO 8601 UTC, TTL не более 600 секунд
- для `top`: `phrase` — только общедоступный поисковый запрос; `region` — `225` для России; `device` — `DEVICE_ALL` (по умолчанию)

Гейт проверки: автор владельца, ровно issue #162, временные рамки, одно действие, нормализация входа, запрет платных запросов, проверка уже опубликованного результата по `command_id`. Дубли не пересылать повторно. Результаты открытые, хотя API-ключ всегда приватен.

## Ограничения

- Это не нативный ChatGPT plugin и не самостоятельное подключение MCP. Мост запускается через GitHub Actions и требует принятия PR.
- Платные действия отключены и реальная тарификация не проверялась.
- В публичных issue могут сохраняться ключевые фразы и агрегированные результаты. Не использовать для дел клиента, содержащих тайну или чувствительную информацию, пока нет приватного возвратного канала.
- При отсутствии ключа под именем `yandex_api` отчёт будет `not_configured`; это не означает ошибку Wordstat.

## Этап 2 — разрешённый платный GetTop (10.11.2026)

Владелец 10 ноября явно разрешил платные запросы, сообщил о положительном балансе AI Studio. Данный PR включает только метод `GetTop`, по официальному тарифу **20 ₽ за 1000 запросов (0,02 ₽ за вызов)**. Никаких повторных сетевых попыток, `GetDynamics` и `GetRegionsDistribution` на этом этапе нет.

Безопасность расходов:
- не более **10 попыток GetTop за UTC-день**; максимальная расчётная стоимость 0,20 ₽ в сутки при действующем тарифе;
- каждая оплачиваемая попытка предварительно резервируется ботом в issue #162 с меткой `status=started`; если резервирование не удалось, обращения к Яндексу **не будет**;
- при повторном событии с тем же `command_id` работник останавливается до вызова Wordstat; не повторять после неоднозначного результата;
- учёт ведётся только по ответам доверенного `github-actions[bot]`, а не по сообщениям посторонних;
- ошибка чтения истории GitHub, заполнение квоты или отсутствие каталога блокируют платный вызов;
- входные данные команды от владельца: публичная поисковая фраза до 80 символов, номер региона, устройство; токен и ID каталога из Actions Secrets.

**Важное условие:** для платной статистики требуется ID каталога Yandex Cloud. В настройках репозитория GitHub Actions Secrets добавить `YANDEX_WORDSTAT_FOLDER_ID` значением `folderId` нужного каталога из панели AI Studio. Секрет `yandex_api` используется как ранее. Значения ключа в issue, чат или код не пересылать. Без каталога worker вернёт `status=not_configured, missing=folder_id`, оплаченного запроса не сделает.

## Проверка первого GetTop, 10.11.2026: HTTP 403 и исправление

Факт: PR #164 объединён, один live GetTop по «ИИ собеседник на русском», регион 225, был отправлен через GitHub Actions. Команда и запись о резервировании доступны в issue #162. Сервер Wordstat вернул HTTP 403; **частотность не получена**. Не утверждать, что списание состоялось или не состоялось: подробного биллингового отчёта нет. Повтор запроса не выполнялся.

Причина не доказана. Официальная документация Yandex Search API по аутентификации уточняет, что при использовании сервисного аккаунта с API-ключом, ролью `search-api.webSearch.user`, `folderId` **можно не передавать**. В нашей первой попытке `folderId` принудительно передавался; если он не соответствует каталогу аккаунта, возможен отказ 403. Другие возможные причины: роль и права ключа, доступ к биллингу. Успешный GetRegionsTree доказал, что этот API-ключ в принципе авторизуется к Wordstat, но не доказал права на GetTop именно в указанном каталоге.

Исправление в отдельном PR: GetTop не передаёт необязательный `folderId` для сервисного ключа; даже если секрет `YANDEX_WORDSTAT_FOLDER_ID` сохранён, он игнорируется для GetTop. Не менять ключ и не удалять секрет ради теста. Защита от повторов, предварительное резервирование, потолок 10 платных попыток в UTC-день и безопасная публикация результатов сохранены.

**После merge PR:** один новый GetTop с новым command_id, без автоматического повтора. При повторном 403 проверять роль `search-api.webSearch.user` сервисного аккаунта на каталоге, область `yc.search-api.execute` и активный биллинг, не раскрывая ключа. Подробности: https://aistudio.yandex.ru/ru/docs/search-api/api-ref/authentication .
