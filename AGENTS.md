# Постоянные инструкции разработчикам ИИ-экосистемы

Область применения: **только** репозиторий `olegendorphine-star/ai-ecosystem`. Он не является частью Gii.

1. Перед началом работы сверить задачу, ветку, состояние репозитория и актуальный `docs/STATUS.md`.
2. Работать в отдельной тематической ветке (`feature/...`, `fix/...`, `docs/...`) от согласованной основы. Не писать напрямую в `main`.
3. На каждое изменение указывать изменённые файлы, условия тестирования, результат, ограничения и Git commit SHA. Создавать Pull Request. Не объединять его автоматически без приёмки.
4. Не вносить в Git пароли, API-ключи, refresh/access tokens, OAuth credentials, пользовательские переписки, персональные данные, реальные логи с идентификаторами, файлы `.env`.
5. Не вызывать платные API, не запускать коммерческие кампании, не публиковать объявления, не отвечать клиентам и не изменять production без отдельного разрешения владельца.
6. Тестировать через фиктивные ключи и mock-ответы до допуска к живому API. Всегда сохранять исходные ошибки и проверять идемпотентность операций записи.
7. Не переносить материалы и код проекта Gii без отдельного письменного решения. Репозиторий Gii: `olegendorphine-star/gii-experiments`.
8. Не считать написанный код доказательством доступности API Авито или наличия авторизации. Любая проверка реального подключения должна быть отмечена как отдельный этап.
9. Указывать, какие действия реально выполнены. Если изменения сделаны лишь локально, не утверждать, что они загружены в GitHub или на сервер.
10. Сведения об аккаунтах, разрешениях и стоимости считать непроверенными, пока они не подтверждены в текущей среде или официальными ответами.

Первое поручение: проверить доступ к будущему репозиторию без push, затем согласовать отдельную ветку и только после этого создавать PR.
