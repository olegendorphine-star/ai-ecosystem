# Прайс-лист для двух объявлений Авито — изолированная кандидатная версия
Дата: 05.11.2026. Статус: **НЕ ПУБЛИКОВАТЬ** до проверки в официальном шаблоне конкретной категории и полноценного отчёта валидатора.

## Цель
По прямому поручению владельца подготовить прайс-лист внутри существующих объявлений Москвы и Санкт-Петербурга, сохранив текст, обложки, стоимость объявления 5 000 ₽, пакетный статус и отсутствие платного продвижения.

## Кандидатный файл
`staging/avito-pricelist-candidate-2026-11-05.xml`. Это копия действующего `docs/avito-feed.xml`, но **не** рабочий фид, и GitHub Pages не использует этот путь для Авито.

Предложенные строки для обоих городов:
- «Аудит бизнеса и поиск точек роста» — от 5 000 ₽, за услугу;
- «Настройка персонального ИИ-ассистента» — от 30 000 ₽, за услугу;
- «Внедрение ИИ-экосистемы для бизнеса» — от 150 000 ₽, за услугу.

Вложенность `PriceList/Service` и точные словари `ServiceName=Своя услуга`, `ServiceStartingPrice=Да`, `ServicePriceType=за услугу` **предварительны**. Использованы сведения из сторонних справочников, не из открывшегося официального шаблона именно нашей ветки: `Предложение услуг → Деловые услуги → IT, дизайн, тексты → Программирование, настройка CRM`. Официальный справочник: https://www.avito.ru/autoload/documentation/templates/1196176#field-PriceList (доступ по правам кабинета).

## Проведённая предварительная проверка
- Две записи исходного рабочего XML; кандидат также содержит две записи.
- Остальные поля по строгому строковому сравнению неизменны: если вычесть два добавленных блока, получается исходный XML посимвольно.
- Ровно 6 `Image` на запись, один `AvitoId=8347570435` у Москвы, у СПб AvitoId в сохранённом фиде ещё отсутствует.
- `Price=5000`, `ListingFee=Package`, `AdStatus=Free` не менялись; никакой POST /autoload/v1/upload, покупки продвижения или записи в Авито не было.

## Критерии допуска в production
1. Считать в кабинете Авито официальный XML-шаблон **именно нашей категории** и точные допустимые значения полей PriceList.
2. Скорректировать XML, если вложенность/справочник отличаются; подтвердить по XML parser + посимвольному сравнению что изменены только блоки PriceList.
3. Передать кандидат в официальный валидатор https://autoload.avito.ru/format/xmlcheck/, дождаться окончательного отчёта, проверить обе записи и отсутствие отклонений.
4. Получить явную приёмку результата; только затем отдельным PR внести проверенный блок в `docs/avito-feed.xml` (сохранить оба ID, два города и 12 URL изображений).
5. После лимита не чаще 1 POST/час применить изменения; фактический успех — live `active` обеих карточек, присутствие прайса на витрине, свежий `success_published`. Не считать успешную GitHub Action доказательством публикации.
6. После результата обновить главный паспорт и журнал на Google Диске.
